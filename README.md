# @discordy-voics/bots

A lean TypeScript SDK for building bots on Discordy. It provides a gateway client with intents, heartbeats and resume, a rate-limited REST client, builders for slash commands, components, modals and embeds, interaction handlers, and webhooks.

- **Guide:** [docs/getting-started.md](docs/getting-started.md) (application, token, invite URL, intents, first bot)
- **API reference:** [docs/api](docs/api/README.md) (generated by TypeDoc)
- **Architecture:** [ARCHITECTURE.md](ARCHITECTURE.md)
- **Example:** [examples/moderation-bot](examples/moderation-bot/README.md) (`/ping`, `/kick`, `/purge`)
- **Changes:** [CHANGELOG.md](CHANGELOG.md)

Requires Node.js 22 or newer.

## Install

The package is published to GitHub Packages. Point the `@discordy-voics` scope at it:

```ini
# .npmrc
@discordy-voics:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

```bash
pnpm add @discordy-voics/bots
```

## Run locally

This repository is a pnpm workspace. The example bot imports the built package, so build first:

```bash
make install     # pnpm install --frozen-lockfile
make build       # tsup: ESM, CJS and type declarations into dist/
cp examples/moderation-bot/.env.example examples/moderation-bot/.env   # fill in your values
pnpm --filter @discordy-voics/moderation-bot-example start
```

`make dev` rebuilds the package on change.

## Test

```bash
make test        # vitest: domain, application, interface and example bot tests
make lint        # eslint plus tsc --noEmit
make docs        # regenerate docs/api; CI fails if it is stale
pnpm coverage    # coverage report
```

Tests use a fake gateway socket, a fake clock and a mocked HTTP transport, so they need no network access and no Discord credentials.

## Docker

The SDK ships as an npm package, so the image is a packaging artifact rather than a service. `make docker` runs lint, typecheck, tests and the build inside a multi-stage build, then produces a non-root runtime image containing the built package:

```bash
make docker
```

## Configuration

The SDK reads no environment variables. Pass configuration to `new Client({...})`:

| Option | Required | Default | Purpose |
|---|---|---|---|
| `token` | yes | none | Bot token from the application's Bot page |
| `intents` | yes | none | Gateway intents as names, bits or a bitfield |
| `gatewayUrl` | no | `wss://discordy-gateway.voics.nl/gateway` | Gateway WebSocket URL |
| `rest.baseUrl` | no | `https://discordy-api.voics.nl/api/v1` | REST base URL |
| `rest.retries` | no | `3` | Retries for 429 and transient 5xx responses |

The example bot reads these variables (validated at startup, see [its `.env.example`](examples/moderation-bot/.env.example)):

| Variable | Required | Purpose |
|---|---|---|
| `DISCORDY_BOT_TOKEN` | yes | Bot token |
| `DISCORDY_APPLICATION_ID` | yes | Application (client) id, a snowflake |
| `DISCORDY_GUILD_ID` | no | Register commands in one guild only |
| `DISCORDY_API_URL` | no | REST base URL, for a local stack |
| `DISCORDY_GATEWAY_URL` | no | Gateway URL, for a local stack |
